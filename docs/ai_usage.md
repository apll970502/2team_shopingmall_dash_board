## 안형준 (hyungjune) — 통합 · 테스트 · 문서화

### 해결하려던 문제

내 컴퓨터에서는 앱이 실행되는데, 팀원이나 다른 사람의 컴퓨터에서도 같은 절차로 실행되는지 확신할 수 없었습니다. 또한 가상환경이나 캐시 파일이 저장소에 올라가지 않도록 `.gitignore`를 올바르게 설정해야 했습니다.

### 질문 내용

- Windows PowerShell에서 Git 명령이 여러 줄을 붙여넣었을 때 실행되지 않는 이유가 무엇인지
- Python 프로젝트에서 `.gitignore`에 가상환경과 캐시를 제외하는 표준 설정이 무엇인지
- `requirements.txt`가 있는데도 다른 환경에서 실행이 실패하는 원인이 무엇인지
- 새 폴더에서 clone 후 실행 재현 테스트를 하는 절차가 어떻게 되는지

### AI가 제안한 내용

- PowerShell에서는 여러 줄 명령을 한 번에 붙여넣으면 줄바꿈이 명령 구분으로 처리되지 않을 수 있으므로 한 줄씩 실행할 것
- `.gitignore`에 `__pycache__/`, `.venv/`, `.ipynb_checkpoints/`, `.env` 등을 포함할 것
- `requirements.txt`에 버전을 고정하지 않으면 설치 시점에 따라 다른 버전이 설치될 수 있다는 점
- 기존 개발 폴더와 완전히 분리된 경로(`C:\temp`)에서 clone 후 새 가상환경을 만들어 실행할 것

### 코드를 나눈 기능 단위

1. `.gitignore` 적용 확인 — 제외 대상 파일이 실제로 Git 추적에서 빠지는지
2. `requirements.txt` 설치 확인 — 빈 가상환경에서 필요한 패키지가 모두 설치되는지
3. 새 폴더 clone 후 실행 재현 — 개발 환경에 의존하지 않고 앱이 실행되는지

### 실제 적용 및 수정 내용

- AI가 제안한 `.gitignore` 예시에 `data/processed/*` 와 `!data/processed/.gitkeep` 를 추가해, 정제 결과는 제외하되 폴더 구조는 유지하도록 수정했습니다.
- 명령을 여러 줄로 안내한 부분을 한 줄씩 실행하는 형태로 바꾸어 문서에 기록했습니다.
- 테스트 경로를 프로젝트 폴더 하위가 아니라 완전히 분리된 `C:\temp` 로 지정했습니다.

### 실행 전 예상

- `.gitignore` 적용 후 `git status` 에 `.venv` 와 `__pycache__` 가 나타나지 않을 것으로 예상
- 새 폴더에서 `requirements.txt` 설치 후 앱이 개발 폴더와 동일하게 실행될 것으로 예상
- `git ls-files data/raw` 에서 CSV 4개가 모두 조회될 것으로 예상

- `git ls-files data/raw` 결과로 `customers.csv`, `order_items.csv`, `orders.csv`, `products.csv` 4개가 모두 조회되었습니다.

- main 브랜치에서 `git log --oneline` 으로 `HEAD -> main` 과 `origin/main` 이 동일한 커밋(`2d72ef8`)을 가리키는 것을 확인했습니다.

### 예외 조건 검증

- 기존 개발 환경에 이미 설치된 패키지에 의존하지 않도록, 완전히 분리된 경로에 새 가상환경을 만들어 테스트했습니다.
- `git ls-files` 로 CSV가 `.gitignore` 에 걸려 누락되지 않았는지 확인했습니다. 데이터 파일이 없으면 새 환경에서 앱이 실행되지 않기 때문입니다.

### 잘못되거나 적용하지 않은 제안

- AI가 `.gitignore` 에 `*.csv` 를 넣는 예시를 제시했으나, 이 프로젝트는 `data/raw` 의 CSV가 저장소에 반드시 포함되어야 하므로 적용하지 않았습니다. 그대로 적용하면 새 환경에서 데이터를 찾지 못해 앱이 실행되지 않습니다.
- 명령을 한 번에 붙여넣는 형태의 안내는 PowerShell에서 실패했으므로 사용하지 않았습니다.

### 새롭게 배운 점

- `requirements.txt` 에 패키지 이름만 적으면 버전이 고정되지 않아, 설치 시점에 따라 다른 버전이 설치될 수 있습니다. 같은 코드가 환경에 따라 다르게 동작하는 원인이 됩니다.
- 개발 폴더에서 앱이 실행되는 것과, 새 환경에서 실행되는 것은 별개의 문제입니다. 새 환경 테스트를 하지 않으면 환경 의존 문제를 발견할 수 없습니다.
- 에러가 없다는 것과 정상이라는 것은 다릅니다. 이번에 발견한 경고는 지금은 동작하지만, 이후 버전에서는 앱이 실행되지 않게 되는 문제였습니다.

## 전예진 (wjs0951467-wq) — 데이터 점검 및 분석

### 해결하려던 문제

CSV 4개를 불러온 뒤, 데이터에 문제가 없는지 먼저 확인하고 하나의 데이터로 합쳐야 했습니다. 그다음 카테고리별·월별 매출과 쇼핑몰 핵심 지표를 계산해야 했는데, 계산 결과가 맞는지 어떻게 확인해야 할지 몰랐습니다.

### 질문 내용

- 주문 상세 데이터를 기준으로 상품, 주문, 고객 데이터를 merge하여 하나의 DataFrame으로 만드는 코드가 올바른지
- 주문 수량과 단가를 이용해 주문 금액을 계산하고, 각 데이터를 병합하는 코드를 초보자가 이해하기 쉽게 작성해달라는 요청
- 병합된 데이터로 고객 수, 총 주문 건수, 총 매출액, 평균 주문 금액(AOV)을 계산하는 코드

### AI가 제안한 내용

- `order_items` 를 기준으로 `product_id`, `order_id`, `customer_id` 순서대로 left merge하는 구조
- 주문 금액을 `quantity * unit_price` 로 계산해 새 컬럼으로 추가하는 방식
- 고객 수와 주문 건수는 `nunique()` 로 중복을 제외하고 세는 방법
- 총 주문 건수가 0일 때 나눗셈 오류를 피하는 조건문

### 코드를 나눈 기능 단위

1. 기본키 중복 및 결측치 점검
2. 주문 금액 계산과 데이터 병합
3. 쇼핑몰 핵심 지표(KPI) 계산

### 실제 적용 및 수정 내용

1. 기본키 중복 여부를 확인할 수 있도록 `duplicated().any()` 를 사용했습니다.
2. 각 데이터의 전체 결측치 개수를 확인할 수 있도록 `isnull().sum().sum()` 을 사용했습니다.
3. 주문 금액을 `quantity * unit_price` 로 계산해 `total_amount` 컬럼을 생성했습니다.
4. 여러 데이터를 각각의 ID 기준으로 left merge하도록 작성했습니다.
5. 고객 수와 주문 건수를 중복 없이 계산하기 위해 `nunique()` 를 사용했습니다.
6. AOV 계산 시 `if total_orders > 0 else 0` 조건을 넣어 0으로 나누는 오류를 막았습니다.

### 실행 전 예상

**데이터 점검** — 각 데이터의 주요 ID에 중복이 없고 결측치도 없을 것으로 예상했습니다. ID가 중복되거나 빈 값이 있으면 문제가 됩니다.

**병합** — 수량과 단가를 곱한 주문 금액이 계산되고, 각 데이터가 ID 기준으로 병합되어 `(14603, 18)` 크기가 될 것으로 예상했습니다. 병합 기준 컬럼이 없거나 ID가 맞지 않으면 오류가 날 수 있다고 보았습니다.

**KPI** — 고객 수, 총 주문 건수, 총 매출액이 계산되고, 총 매출액을 주문 건수로 나눈 평균 주문 금액이 나올 것으로 예상했습니다. 주문 건수가 0이면 나눗셈 오류가 발생할 수 있습니다.

## 전예진 (wjs0951467-wq) — 데이터 점검 및 분석

### 해결하려던 문제

CSV 4개를 불러온 뒤, 데이터에 문제가 없는지 먼저 확인하고 하나의 데이터로 합쳐야 했습니다. 그다음 카테고리별·월별 매출과 쇼핑몰 핵심 지표를 계산해야 했는데, 계산 결과가 맞는지 어떻게 확인해야 할지 몰랐습니다.

### 질문 내용

- 주문 상세 데이터를 기준으로 상품, 주문, 고객 데이터를 merge하여 하나의 DataFrame으로 만드는 코드가 올바른지
- 주문 수량과 단가를 이용해 주문 금액을 계산하고, 각 데이터를 병합하는 코드를 초보자가 이해하기 쉽게 작성해달라는 요청
- 병합된 데이터로 고객 수, 총 주문 건수, 총 매출액, 평균 주문 금액(AOV)을 계산하는 코드

### AI가 제안한 내용

- `order_items` 를 기준으로 `product_id`, `order_id`, `customer_id` 순서대로 left merge하는 구조
- 주문 금액을 `quantity * unit_price` 로 계산해 새 컬럼으로 추가하는 방식
- 고객 수와 주문 건수는 `nunique()` 로 중복을 제외하고 세는 방법
- 총 주문 건수가 0일 때 나눗셈 오류를 피하는 조건문

### 코드를 나눈 기능 단위

1. 기본키 중복 및 결측치 점검
2. 주문 금액 계산과 데이터 병합
3. 쇼핑몰 핵심 지표(KPI) 계산

### 실제 적용 및 수정 내용

1. 기본키 중복 여부를 확인할 수 있도록 `duplicated().any()` 를 사용했습니다.
2. 각 데이터의 전체 결측치 개수를 확인할 수 있도록 `isnull().sum().sum()` 을 사용했습니다.
3. 주문 금액을 `quantity * unit_price` 로 계산해 `total_amount` 컬럼을 생성했습니다.
4. 여러 데이터를 각각의 ID 기준으로 left merge하도록 작성했습니다.
5. 고객 수와 주문 건수를 중복 없이 계산하기 위해 `nunique()` 를 사용했습니다.
6. AOV 계산 시 `if total_orders > 0 else 0` 조건을 넣어 0으로 나누는 오류를 막았습니다.

### 실행 전 예상

**데이터 점검** — 각 데이터의 주요 ID에 중복이 없고 결측치도 없을 것으로 예상했습니다. ID가 중복되거나 빈 값이 있으면 문제가 됩니다.

**병합** — 수량과 단가를 곱한 주문 금액이 계산되고, 각 데이터가 ID 기준으로 병합되어 `(14603, 18)` 크기가 될 것으로 예상했습니다. 병합 기준 컬럼이 없거나 ID가 맞지 않으면 오류가 날 수 있다고 보았습니다.

**KPI** — 고객 수, 총 주문 건수, 총 매출액이 계산되고, 총 매출액을 주문 건수로 나눈 평균 주문 금액이 나올 것으로 예상했습니다. 주문 건수가 0이면 나눗셈 오류가 발생할 수 있습니다.
