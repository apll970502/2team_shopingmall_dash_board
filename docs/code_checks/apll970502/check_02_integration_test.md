## 6. 정상 조건 검증
개별 브랜치가 아니라 merge된 develop 브랜치에서 실행했으므로
A와 B의 코드가 서로 맞물려 동작하는 것을 확인한 것이다.
필터를 여러 값으로 바꿔가며 지표와 차트가 함께 변하는지 확인했다.

- 개별 기능 확인이 아니라 merge 후 통합 동작 확인에 초점을 맞춤

## 9. 내 말로 설명
각자 브랜치에서 잘 돌아갔으니까 합쳐도 당연히 돌아가겠지 
생각했는데 그게 아니라는것이 신기했다 그냥 덮어쓰기형태로 이어나갈줄 알았다

예진 님이 만든 함수 이름과 진님이 그 함수를 부르는 이름이 
다르면 각자 컴퓨터에서는 문제가 없어도 합친 순간 에러가 난다. 
그래서 합쳐진 develop 브랜치에서 다시 실행해보는 과정그리고 만들때마다 각자 local 데이터를 최신화하면서 속돌르 맞춰간다는게 2인3각 달리기하는것같았다





## 10. 아직 이해되지 않는 부분
merge할 때 Git이 어떻게 이 줄은 A가 바꿨고 이 줄은 B가 
바꿨다를 구분해서 자동으로 합치는지 그 원리가 아직 이해되지 않는다.

그 기준이 무엇인지 더 알아보고 싶다
