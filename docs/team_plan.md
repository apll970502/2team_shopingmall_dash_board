## 4. 브랜치 전략

```
hyungjune / yejin / jin   (개인 작업 브랜치)
        ↓  Pull Request + 리뷰
     develop              (통합 브랜치)
        ↓  Pull Request
      main                (검증 완료된 코드만 유지)
```

## 5. 팀 협업 규칙

- `main` 에 직접 push 하지 않는다
- 작업을 시작하기 전 최신 브랜치를 먼저 받아 맞춘다
- 기능 단위로 브랜치를 만든다
- 병합은 Pull Request로만 진행한다
- 가능하면 PR 작성자가 아닌 다른 팀원이 Merge한다
- 충돌은 혼자 처리하지 않고 팀에 알린다
- 검증되지 않은 코드는 `main` 에 병합하지 않는다

## 6. AI 활용 원칙

- AI에 전체 코드를 한 번에 요청하지 않고, 기능 단위로 나누어 요청한다
- 받은 코드는 반드시 직접 실행하고, 출력값을 원본 데이터와 대조해 확인한다
- 실제 API 키, 비밀번호, 개인정보는 AI에 입력하지 않는다
- 본인이 설명할 수 없는 코드는 최종 결과에 포함하지 않는다
- 각자 최소 3개의 코드 단위 검증 기록을 작성한다
