### 발생한 문제

1. PowerShell에서 여러 줄로 붙여넣은 Git 명령이 실행되지 않았습니다.
2. develop 브랜치가 main보다 뒤처진 상태로 남아 있었습니다.
3. 새 환경에서 실행했을 때 개발 폴더에는 없던 Streamlit 경고(`use_container_width` 제거 예정)가 출력되었습니다.
4. `git switch develop` 입력 중 오타로 불필요한 파일이 생성되었습니다.

### 해결 방법

1. 명령을 한 줄씩 실행하고, 성공한 순서를 문서에 기록해 이후 같은 절차로 재현할 수 있게 했습니다.
2. main을 develop에 병합해 두 브랜치를 동일한 상태로 정리했습니다.
3. `requirements.txt` 에 버전이 고정되어 있지 않아 새 환경에 더 최신 버전이 설치된 것이 원인임을 확인했습니다.
4. 커밋 전 `git status` 로 발견해 파일을 삭제했습니다. 커밋 전 확인 절차의 필요성을 확인했습니다.

### 본인이 이해한 내용

- 브랜치는 나누는 것보다 합치는 순서가 중요합니다. 늦게 병합할수록 공용 파일에서 충돌이 커집니다.
- `import` 오류는 문법 문제가 아니라 폴더 구조와 실행 위치의 문제였습니다.
- `requirements.txt` 는 단순한 목록이 아니라, 다른 사람이 같은 환경을 만들 수 있게 하는 기준입니다.
- 개발 폴더에서 앱이 실행되는 것과, 새 환경에서 실행되는 것은 별개의 검증 항목입니다.
- 에러가 없다는 것이 정상이라는 뜻은 아닙니다. 경고도 이후 버전에서 실행 실패로 이어질 수 있습니다.

### 아직 이해되지 않는 내용

- `rebase` 와 `merge` 를 언제 어느 쪽으로 선택해야 하는지 기준을 아직 감으로 판단하고 있습니다.
- 가상환경이 패키지를 어떻게 격리하는지, 버전을 고정해야 하는 원리까지는 정확히 이해하지 못했습니다.
- Streamlit이 화면을 다시 그리는 시점과 캐시가 동작하는 조건을 정확히 예측하지 못합니다.

### 발생한 문제

1. AI가 제안한 코드에 실제로 사용하지 않은 함수명(`load_data()`, `merge_datasets()`)이 포함되어 있어, 그대로 기록하면 실제 코드와 맞지 않았습니다.
2. 병합 후 계산한 고객 수(1,102명)가 원본 `customers.csv` 의 행 수(1,200)와 달랐습니다.
3. 평균 주문 금액을 계산할 때 주문 건수가 0이면 나눗셈 오류가 발생할 수 있었습니다.

### 해결 방법

1. 노트북에서 실제로 실행한 코드 형태를 그대로 유지하고, 사용하지 않은 함수 구조는 기록에서 제외했습니다.
2. 병합된 데이터는 주문 상세 기준이므로 주문 이력이 없는 고객이 제외된다는 것을 확인했습니다. 따라서 1,200명은 전체 고객 수, 1,102명은 주문한 고객 수로 구분해야 합니다.
3. `if total_orders > 0 else 0` 조건을 넣어 0으로 나누는 오류를 방지했습니다.

### 본인이 이해한 내용

- 데이터를 분석하기 전에 ID 중복과 결측치를 먼저 확인해야 합니다. 중복이 있으면 병합할 때 행이 비정상적으로 늘어납니다.
- 병합 후 행 수를 원본과 대조하는 것이 병합이 제대로 됐는지 확인하는 방법이었습니다. 에러가 없다고 해서 정상은 아닙니다.
- 주문 금액은 데이터에 원래 있는 값이 아니라, 수량과 단가를 곱해 직접 만들어야 하는 값이었습니다.
- 같은 "고객 수"라도 어느 데이터를 기준으로 세는지에 따라 값이 달라집니다.
- AOV는 총 매출액을 주문 건수로 나눈 값으로, 한 번 주문할 때 평균적으로 쓰는 금액을 뜻합니다.

### 아직 이해되지 않는 내용

- `merge()` 에서 `how="left"` 를 사용하는 이유를 완전히 이해하지 못했습니다.
- 여러 데이터를 병합할 때 행이 어떻게 연결되는지 아직 익숙하지 않습니다.
- `duplicated()` 와 `any()` 의 각 역할, `isnull().sum().sum()` 이 결측치를 세는 과정이 아직 익숙하지 않습니다.
- `nunique()` 가 중복을 제외하고 세는 원리와, AOV가 실제 쇼핑몰 분석에서 어떻게 활용되는지는 더 공부가 필요합니다.

### 해결 방법

3. 데이터를 Series에서 단일 컬럼 DataFrame으로, 색상 인자를 문자열에서 리스트로 변경했습니다.

### 본인이 이해한 내용

- 빈 데이터는 CSV 자체가 비어 있는 경우와, 파일은 정상인데 필터 조합에 해당하는 데이터가 없는 경우로 나뉩니다. 원인이 다르면 처리도 달라야 합니다.
- 카테고리 필터는 products에서 product_id 목록을 뽑고, 그 목록으로 order_items를 좁히고, 남은 order_id로 orders를 좁히는 순서로 단계적으로 동작합니다.
